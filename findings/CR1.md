- **CR1-2** — **Impact:** A user who upgrades from an incompatible preview record cannot edit or recover All sites defaults while connected, despite the recovery warning; disconnecting the active page happens to change the reset target but is not presented as the recovery procedure. **Invariant:** Every rejected persistent format must have a reachable operation that clears that exact record in every popup connectivity state. **Checked:** The connected initial scope is `user-origin`; the invalid `user-extension` scope is disabled and `ActionSettings` refuses selection of disabled scopes, while `resetLayer()` resolves to the active site scope. **Proof:** Add a Home test with `status="connected"`, a valid snapshot, and `extensionConfigRead().kind === "future-version"`; click Reset and confirm it, then assert `clearUserExtension` was called and `clearSiteLocal` was not. The current implementation calls the latter. **Fix:** When `extensionNeedsReset()` is true, render a dedicated All sites recovery action or force `resetLayer()` to `user-extension`, independently of the editor scope, and cover all three rejected read kinds in connected and disconnected tests.

- **CR1-3** — **Impact:** First-run users can permanently dismiss the guide without creating the destination required by the primary feature; the extension variant also treats an empty custom template as success. **Invariant:** Completing guided setup must persist a usable editor destination unless the user takes the separately labeled Skip setup action. **Checked:** The default `vscode` value is only a suggestion when it comes from the default layer: `resolveEditor()` returns `needs-selection`. - **CR1-4** — **Impact:** SSR/native Node consumers of `@locator/runtime`, and CommonJS users of `locatorjs`, receive `ERR_MODULE_NOT_FOUND` at import time even though the package tarball/bundling contract is green. **Invariant:** Every advertised export condition must load under the repository’s pinned Node runtime after packing and installation. **Checked:** The build emits ESM syntax with imports such as `./functions/reportSetupErrors` but neither `.mjs`/`.cjs` artifacts nor a `type` declaration establishes a valid native module graph. `check-package-contract.js` bundles runtime and `locatorjs` only into its webpack web consumer, so webpack resolves the imports and masks the native-loader failure. **Proof:** After building the packages and selecting pinned Node v22.23.2, `node -e 'import("./packages/runtime/dist/index.server.js")'` fails on missing `dist/functions/reportSetupErrors`; from `packages/locatorjs`, `node -e 'require(".")'` fails on missing `packages/shared/dist/isValidRenderer`. **Fix:** Publish a coherent dual package: fully specified ESM `.mjs` output for `import`, CommonJS `.cjs` output for `require`, and explicit conditional exports. - **CR1-5** — **Impact:** Clicking or copying a location for code resolved into a sibling workspace opens a path such as `/Users/me/app/Users/me/app-old/src/page.tsx`, so LocatorJS fails at its core source-navigation job. **Invariant:** A source-map path known to be absolute must remain absolute even when it lies outside the configured project root. **Checked:** Inside-root POSIX paths and outside-root Windows drive paths are handled; the failure comes from the intentional ambiguity between legacy project-relative `/src/file.tsx` values and genuine absolute POSIX values. `sourceMapResolver` supplies the latter, so merely treating every leading slash as absolute would break existing relative inputs. **Proof:** `resolveSourcePath("/Users/me/app-old/src/page.tsx", "/Users/me/app").absolute` returns `/Users/me/app/Users/me/app-old/src/page.tsx`; the current unit test at `sourcePath.test.ts:47` locks in that fabricated result. **Fix:** Carry path provenance (absolute versus project-relative) from adapters/source-map resolution into `resolveSourcePath`, preserve legacy `/src` behavior only for callers that mark it relative, and change the sibling-root test to require the original absolute path.

- **CR1-6** — **Impact:** A confirmed reset can appear successful and then silently restore stale defaults, including the invalid record the user was trying to clear. **Invariant:** A successful clear is an ordering barrier after every mutation accepted before it and before every mutation accepted after it. **Checked:** `mutate()` chains reads and writes through `pendingMutation`, whereas `clearExtensionConfig()` calls storage removal directly and resets `readinessPromise`; the popup immediately overwrites its signals with the empty state, so it cannot reveal a late write. **Proof:** In a storage-contract test, defer `browser.storage.local.set`, start `patchExtensionConfig`, call `clearExtensionConfig`, then release the set and await both operations; the key is present after the reported successful clear. **Fix:** Put clear operations onto the same `pendingMutation` chain and update readiness only when the queued removal succeeds; test both patch-before-clear and patch-after-clear ordering.

- **CR1-7** — **Impact:** Applications that intentionally start Locator disabled cannot inspect components inside closed web-component roots created before re-enabling it. **Invariant:** Discoverability of closed roots created after successful setup must not depend on whether the visual runtime is currently enabled. **Checked:** The extension’s document-start MAIN hook installs tracking unconditionally, so this affects library setup rather than the extension path. A later `scan(document)` can find open `node.shadowRoot` values only; closed roots are recoverable solely when the patched `attachShadow` registered them at creation. **Proof:** Set up with `{ disabled: true }`, attach a closed root before changing the effective layer to enabled, activate over a child, and assert the child can be resolved; current behavior returns the host because the registry never saw the root. **Fix:** Install the lightweight `attachShadow` registry immediately after every successful browser `setup()`, independently of the enabled/UI state, while keeping visual runtime loading conditional.
